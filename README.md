# SEMP — Smart Energy Monitoring and Prediction

A full-stack home energy monitoring system that tracks power usage device by
device, flags unusual consumption before it costs you, forecasts your next
bill, and gets out of the way otherwise.

**Live app:** https://semp-nu.vercel.app/

Built as a final-year Computer Science project (Mount Kenya University),
combining a MERN + TypeScript web app with a Python ML pipeline for
forecasting and anomaly detection.

---

## What it does

- **Real-time tracking** — live power draw per device, plus daily/weekly/monthly trend charts
- **Category breakdown** — which appliance categories are actually driving the bill
- **Anomaly detection** — unusual device draw triggers a live alert with a one-click "turn it off" action
- **Bill forecasting** — tariff-aware predictions (KES) with a confidence band, plus per-device forecasts
- **Budgeting** — monthly budget with cost alerts as usage approaches the limit
- **Weekly email digests** — automated PDF/HTML usage summary, Monday mornings (Africa/Nairobi)
- **Per-device detail pages** — lifetime usage, average/peak draw, anomaly history, usage trend
- **Room/category grouping** — organize devices however makes sense for the household
- **Installable PWA** — add-to-home-screen support (Chromium/Android)
- **Guided onboarding** — new accounts get a walkthrough instead of empty charts

│   ml          │──POST──▶  │   server      │ ◀──────▶│   app            │

└───────────────┘            │  digests      │          └──────────────────┘
                             └──────┬────────┘
                                    │

Telemetry is also generated by a lightweight Node-side simulator in
`server/` (no real smart-plug hardware yet) so the dashboard has continuous
data even between ML pipeline runs.

| Part                 | Stack                                                   | Hosted on               |
| -------------------- | ------------------------------------------------------- | ----------------------- |
| [`app`](./app)       | React 19, Vite, TypeScript, Bootstrap, socket.io-client | Vercel                  |
| [`server`](./server) | Express 5, Mongoose 9, TypeScript, JWT, Zod, socket.io  | Render                  |
| [`ml`](./ml)         | Python, Flask, scikit-learn, APScheduler, NILMTK        | Run locally / scheduled |

Each folder has its own README with full setup, environment variables, and
scripts. This file is the map; theirs are the manual.

## Getting started

Clone the repo, then bring the three parts up in this order — the app
expects live data, so the pipeline needs to have run at least once against a
running server before there's anything to render.

```bash
# 1. Server
cd server
npm install
cp .env.example .env   # see server/README.md
npm run dev

# 2. ML pipeline (separate terminal)
cd ml
pip install -r requirements.txt
cp .env.example .env   # see ml/README.md
python app.py

# 3. App (separate terminal)
cd app
npm install
cp .env.example .env   # see app/README.md
npm run dev
```

## Status / known limitations

- **Device scheduling/automation** (per-device time-based on/off rules) is built but currently paused/unmerged — it sits outside this project's documented thesis scope for now.
- Telemetry beyond the ML pipeline's own data is currently simulated (no real smart-plug hardware integration yet) — the simulator is written so swapping in real hardware later only requires replacing the inside of one function.
